# كدّ (Kadd)

قفل التطبيقات بالمجهود الجسدي أو بالتزام الصلاة. هذا مستودع Flutter كامل،
مع سير عمل GitHub Actions يبني ملف APK تلقائيًا بمجرد أن تدفع (push) الكود —
نفس النمط المستعمل سابقًا لـ Sufra.

**قبل النشر على Play Store، اقرأ `PLAYSTORE_CHECKLIST.md`** — يغطي التوقيع
(إلزامي، والبناء الحالي بلا توقيع خاص لا يكفي لـ Play Store)، تبرير
الصلاحيات الحساسة، وسياسة الخصوصية (`PRIVACY_POLICY.md`، مسودة جاهزة
تحتاج فقط استضافة ورابط عام).

## تحديث كبير: تطبيقات حقيقية بدل لائحة ثابتة، ومدينة بدل GPS

بناءً على تجربة حقيقية على الهاتف، تغيّرين أساسيتين:

1. **اختيار التطبيقات صار حقيقيًا** — بدل لائحة ثابتة من 5 تطبيقات
   (تيك توك، إنستغرام...)، `SettingsScreen` دابا كيعرض التطبيقات المقفلة
   الحقيقية بأسمائها وأيقوناتها الفعلية، وزر "إضافة تطبيق"
   (`app_picker_screen.dart`) يفتح قائمة كل تطبيقاتك المثبتة (حزمة
   `installed_apps`) لتختار منها أي واحد تريد قفله. هذا يحتاج صلاحية
   `QUERY_ALL_PACKAGES` — راجع `PLAYSTORE_CHECKLIST.md` لتبريرها فنموذج
   Play Console.
2. **الموقع الجغرافي تشال بالكامل** — مواقيت الصلاة دابا عبر اختيار مدينة
   يدويًا من قائمة مدن مغربية (`lib/models/city.dart`) بدل GPS، عبر
   Aladhan API's `timingsByCity` بدل الإحداثيات. صلاحية موقع واحدة أقل
   يعني مراجعة Play Store أسهل، وخصوصية أوضح للمستخدم.

`lib/models/locked_app.dart` تبسّط أيضًا: عاد ما فيهش اسم/إيموجي مُبرمَج
مسبقًا — الاسم والأيقونة يتقروا حيّة من الجهاز عبر `AppState.displayNameFor()`
و`AppState.iconFor()`، فيبقاو دايمًا يعكسو الواقع حتى لو تبدّل اسم التطبيق
أو تحيّد.

## كيفاش ترفعه لـ GitHub وتبني الـ APK تلقائيًا

```bash
# داخل مجلد kadd بعد فك الضغط:
git init
git add .
git commit -m "kadd: initial scaffold"

# باستعمال GitHub CLI (الأسهل، إذا مثبّت gh ومسجّل دخول):
gh repo create kadd --private --source=. --push

# أو يدويًا: أنشئ مستودع فارغ من واجهة GitHub، ثم:
git remote add origin https://github.com/<اسمك>/kadd.git
git branch -M main
git push -u origin main
```

بعد أول push، افتح تبويب **Actions** فمستودعك على GitHub — سير العمل
`Build APK` غادي يخدم تلقائيًا، وفـ النهاية يحط ملف الـ APK كـ **Artifact**
قابل للتحميل (اسمه `kadd-apk`) من نفس صفحة التشغيل (run).

## البناء محليًا (بلا انتظار GitHub)

```bash
flutter --version   # تأكد عندك Flutter مثبّت
./scripts/build_local.sh            # نسخة debug
./scripts/build_local.sh --release  # نسخة release
```

هاد السكريبت كيدير بالضبط نفس خطوات الـ CI: يولّد مجلد `android/`، ينسخ
ملفات Kotlin، يرقّع `AndroidManifest.xml`، ثم يبني الـ APK.

## ليش `android/` مش موجود فالمستودع؟

المستودع ما فيهش مجلد `android/` جاهز — كيتولّد تلقائيًا فكل مرة (عبر
`flutter create --platforms=android .`) ثم يترقّع بملفات `android_additions/`.
هاد الاختيار مقصود: بدل ما نحافظ يدويًا على نسخة Gradle/Kotlin boilerplate
كاملة قد تتقادم مع كل تحديث لـ Flutter، الـ CI يولّدها فريش فكل مرة بأحدث
نسخة متوافقة، ويرقّعها بمكوناتنا الخاصة (الخدمة، الأنشطة، المستقبِلات).
هذا يعني أيضًا أن `android/` مذكور فـ `.gitignore` عمدًا.

## القرارات التقنية المهمة

- **القفل عبر UsageStatsManager + Foreground Service، وليس AccessibilityService.**
  سياسة Google Play تقيّد استعمال Accessibility API لحالات إتاحة حقيقية،
  وتطبيقات قفل الشاشة رُفضت/أُزيلت سابقًا لاستعمالها كحل بديل.
- **مواقيت الصلاة عبر Aladhan API بطريقة الحساب رقم 21** (وزارة الأوقاف
  المغربية)، مبنية على GPS مباشرة بدل اختيار مدينة يدويًا.
- **عد التكرارات (عقلات) عبر زاوية المرفق** من نقاط ML Kit Pose Detection.
- **`android/` غير مُصدَّر بالمستودع** — يتولّد ويترقّع تلقائيًا (انظر أعلاه).

**منجز أيضًا:** بانر فالشاشة الرئيسية يطلب صلاحية "الوصول للاستخدام" (Usage
Access) إذا لم تُمنح بعد — بدونها، `LockForegroundService` ما يقدرش يعرف
أي تطبيق مفتوح حاليًا، فالقفل كامل ما يخدمش. يتحقق تلقائيًا عند كل عودة
للتطبيق (`didChangeAppLifecycleState`) بعد ما يرجع المستخدم من الإعدادات.

## إصلاحات على أخطاء بناء حقيقية

ثلاث أخطاء ظهرت عند أول `flutter run` حقيقي، مُصلَّحة الآن:

1. **`TextDirection.rtl` غير موجود** فـ `prayer_settings_screen.dart` — سببه
   أن `package:intl/intl.dart` يُصدّر كلاس خاص به اسمه أيضًا `TextDirection`،
   فيتعارض مع `dart:ui`'s ويُخفي القيم الصحيحة (`ltr`/`rtl`). الحل:
   `import 'package:intl/intl.dart' hide TextDirection;`
2. **`emoji`/`labelAr` غير معرّفين على `PrayerName`** — نفس الملف كان ناقص
   `import '../models/prayer.dart';` المباشر (الاستيراد غير المباشر عبر
   `app_state.dart` ما يكفيش لجلب الـ extension methods لنطاق الملف).
3. **`tflite_flutter` فشل بالبناء** (`UnmodifiableUint8ListView` غير معرّف) —
   علة غير محلولة فالحزمة نفسها مع إصدارات Dart SDK الحديثة. استبدلتها
   بـ `google_mlkit_image_labeling` (راجع `assets/models/README.md`).

## تتبع حي للرأس واليدين (رجعت لبناء هذا بعد نجاح أول تشغيل)

`rep_camera_screen.dart` صار يرسم فوق الكاميرا مباشرة نقاط الرأس (الأنف)
واليدين (المعصمين)، بلون رمادي خافت لباقي الهيكل كسياق بصري، وتتحول النقاط
الثلاث المتتبَّعة لـ **أخضر** فور الوصول للوضعية الجيدة (الرأس قريب من
مستوى اليدين، أي قريب من الأرض). العدّ نفسه صار مبنيًا على نفس هذه المسافة
(رأس↔يدين) بدل زاوية المرفق وحدها:

- `lib/widgets/coordinates_translator.dart` — يحوّل إحداثيات النقاط من
  فضاء صورة الكاميرا الخام إلى فضاء الشاشة (نفس المعادلات المستعملة فأمثلة
  ML Kit الرسمية، تراعي الدوران والانعكاس الأفقي للكاميرا الأمامية).
- `lib/widgets/pose_painter.dart` — `CustomPainter` يرسم الهيكل والنقاط.
- عتبات المسافة (`_downGapRatio = 0.12`, `_upGapRatio = 0.30` فـ
  `rep_camera_screen.dart`) **تقديرية** — أول شيء تضبطه بعد ما تشوف
  التتبع حي على جهازك: إذا ما تتحولش النقاط لأخضر رغم نزولك بشكل صحيح،
  زِد `_downGapRatio` شوية؛ إذا العدّ ما يسجلش رغم رفعك بذراع كامل، نقّص
  `_upGapRatio`.
- زدت أيضًا debounce (`_framesToConfirm = 3` إطارات متتالية قبل ما يتغير
  الوضع) و cooldown (`_minRepInterval = 500ms` بين كل عقلة والتالية) —
  حماية من عدّ خاطئ بسبب رعشة/ضبابية إطار واحد. إذا حسّيتي العدّ بطيء
  الاستجابة، نقّص `_framesToConfirm`؛ إذا كيعدّ عقلات وهمية، زِده.

## مرحلة التلميع (وصلنا لمستوى أقم — بالتدريج)

1. **الواجهة**: خلفية بتوهج مرسومة يدويًا (`lib/widgets/kadd_background.dart`،
   CustomPainter بدل تدرج CSS عادي)، وبطاقات موحدة (`kadd_card.dart`) بدل
   ما كل شاشة تعرّف `BoxDecoration` بشكل منفصل — الآن الشاشات الأربع
   الرئيسية + شاشة قفل الصلاة كلها تستعمل نفس النظام.
2. **التجربة**: اهتزاز (haptic) عند كل عقلة وعند اكتمال المجموعة، شاشة
   احتفال قصيرة (✓ خضراء + "كدّيتها! 💪" / "تقبّل الله 🤲") بدل ما التطبيق
   يقفل الكاميرا بصمت، ونبضة خفيفة مستمرة على أيقونة القفل فشاشة انتظار
   الصلاة.
3. **التقني**: مراجعة شاملة بعد استرجاع الملفات (انظر أدناه) — تأكدت كل
   الشاشات المعاد بناؤها تطابق `AppState`/`main.dart`/الموديلات بلا أي
   تعارض أسماء أو استيراد ناقص.

## ملاحظة: انقطاع فالبيئة أثناء البناء

فمرحلة من هذا المشروع، البيئة اللي كنخدم فيها تصفرت (session reset) وضاعت
نسخة عملت شغل UI متقدم قبل ما تُحفظ. تعلمت من هذا: كل تعديل مهم دابا كيتزيّب
فورًا لملف الإخراج بدل ما ننتظر لنهاية الجلسة. إذا لاحظتي أي تراجع غريب فشي
ميزة كانت خدامة من قبل، هذا السبب الأرجح — قوليا ونرجعها.

## الحالة الحقيقية — ما ينقص قبل الإطلاق

1. **نموذج تصنيف السجادة (الملف نفسه) غير موجود بعد** — الكود اللي يحمّله
   ويشغّله جاهز بالكامل (`lib/services/rug_classifier.dart`، يتعامل تلقائيًا
   مع float32 وquantized). الناقص فقط هو `assets/models/rug_classifier.tflite`
   نفسه — راجع `assets/models/README.md` لخطة جمع البيانات والتدريب
   (Teachable Machine كحل سريع للنسخة الأولى). حتى يوجد الملف، `RugScanScreen`
   يفشل بصمت ويرجّع ثقة 0.0 دائمًا — فشل آمن، لا فتح خاطئ.
2. **منبهات الأذان بعد إعادة تشغيل الهاتف غير مُعاد جدولتها تلقائيًا** —
   `BootReceiver.kt` يعيد تشغيل خدمة القفل (فيشتغل قفل العقلات مباشرة)، لكن
   قفل الصلاة يحتاج شبكة فقط الآن لجلب المواقيت (المدينة محفوظة مسبقًا، لا
   GPS يُطلب)، وهذا ما تقدرش تضمنه BroadcastReceiver عادية بسهولة.
   `AppState.init()` يعيد الجلب والجدولة عند كل فتح للتطبيق، وهذا يكفي
   عمليًا للإصدار الأول.
3. **لم يُختبَر بعد على جهاز حقيقي: منتقي التطبيقات ومنتقي المدينة** —
   `app_picker_screen.dart` (يعتمد على `QUERY_ALL_PACKAGES`) وحوار اختيار
   المدينة الجديدين لم يُجرَّبا بصريًا على جهاز حقيقي بعد. الكاميرا/التتبع/
   القفل الأساسي مُجرَّبون فعليًا وخدموا حسب آخر تجربة.
4. **اختبار المنبهات على أجهزة Xiaomi/Huawei/Samsung** — هذه الشركات معروفة
   بتقييد التنبيهات الخلفية بقوة؛ قد تحتاج توجيه المستخدم يدويًا لتعطيل توفير
   الطاقة للتطبيق.

## الخطوة التالية المقترحة

ادفع المستودع لـ GitHub وشوف واش سير العمل يخدم أول مرة بلا مشاكل — هذا
أول اختبار حقيقي للمشروع كامل. إذا فشل البناء، الأرجح أن يكون بسبب توافق
إصدار Flutter/Gradle مع `tflite_flutter` أو `google_mlkit_pose_detection`
(يحتاجان أحيانًا رفع `minSdkVersion` أو NDK معيّن) — أرسل لي رسالة الخطأ من
تبويب Actions ونحلها.
